## What this package does

Running `run.do` reproduces the figures and tables in the manuscript and the Supplementary
Information that are generated by code:

- **5 of the 8 main figures** (Figures 4 to 8). Figures 1 to 3 are drawn in PowerPoint and
  QGIS; see `docs/data_provenance.md`.
- **9 of the 11 SI figures** (S2 to S8, S10, S11). Figure S1 is a PowerPoint diagram and
  Figure S9 reproduces a survey instrument item.
- **23 of the 27 SI tables.** Tables S18 to S21 are produced by `01_clean_data.do`, which
  needs the raw survey data and is therefore not part of the public run; see below.

Neither main-text table is generated by code; both are conceptual tables typeset in Word.

`docs/verification.md` records the reproduction check against the published Supplementary
Information.

`docs/crosswalk.md` maps every published figure and table to the script and output file that
produces it.

## Getting the package

Code is on GitHub; the data are on Zenodo because they exceed GitHub's file-size limits.

- Code: <https://github.com/IvoSteimanis/PES-Mozambique>
- Data: `https://doi.org/10.5281/zenodo.<ID>` — Zenodo concept DOI, resolves to the latest
  version. **Deposit pending; DOI to be filled in.**

Download both, then unpack the Zenodo archive into the repository root so that `data/` and
`processed/` sit next to `run.do`.

## Requirements

- **Stata 19** (the published results were produced under StataNow 19 on Windows 11). The
  code sets `version 19`. Stata 16 and later should work; earlier versions are untested.
- No Stata add-ons need to be installed. Every package used is vendored in
  `scripts/libraries/stata`, and `run.do` points `adopath` at that folder before running
  anything, so results do not depend on what happens to be installed on your machine. See
  `docs/software_versions.md`. `scripts/00_install_packages.do` rebuilds the library from
  source but is **not** part of the normal run.
- Approximately 1 GB of free disk space beyond the data.
- Python and QGIS are needed only to rebuild inputs that are not part of this pipeline
  (see `docs/data_provenance.md`).

## Running it

In Stata, change the working directory to the folder containing `run.do`, then run it:

```stata
cd "/path/to/replication"
do run.do
```

Every path inside the package is relative to that folder, so it runs from any location on any
platform. `run.do` checks that it is in the right directory and that the data archive has been
unpacked, and stops with a clear message if not.

Expected runtime: about 25 to 40 minutes on a current desktop, dominated by the propensity
score matching in scripts 02 to 04 and by the multiple imputation in script 11.

For a clean run, delete `results/` first. Keep `processed/`: it holds the analysis-ready
data and, without the raw data, cannot be regenerated.

A timestamped log is written to `scripts/logs/`.

## Data availability and confidentiality

The **grid-cell remote-sensing data** carry no personal information and are distributed in
full via Zenodo.

The **household survey** is distributed in de-identified form only. Respondent names, phone
numbers, GPS coordinates, enumerator identifiers, interview timestamps, village names and all
open-ended free-text responses have been removed. Villages appear as anonymous numeric codes.
Every removal is marked `CONFIDENTIALITY` in `scripts/01_clean_data.do`.

`01_clean_data.do` is therefore shipped for inspection but **cannot be executed** from the
public package: it needs the raw survey export, which is withheld. `run.do` has the call to it
commented out for this reason. The pipeline starts from the de-identified data in `processed/`,
and every result in the paper is reproducible from there.

### Ethics and consent

Written informed consent was obtained from every respondent, recorded on tablets at the point
of interview. The consent record and its attachment are treated as identifying information and
are removed during cleaning, so they do not appear in the distributed data. The consent and
ethics declarations were filed with the journal at submission.

Researchers who need the raw survey data should contact the corresponding author. Access
requires a confidentiality agreement.

The Hansen Global Forest Change rasters are public and are not mirrored here; download
instructions are in `docs/data_provenance.md`.

Note for anyone redistributing this package: `results/` and `scripts/logs/` are generated
locally and are **not** part of the distributed archive. Stata writes the absolute path of
the machine that produced them into log headers, including the headers of
`results/tables/tableS11_rosenbaum_bounds.txt` and
`results/tables/tableS20_S21_factor_agency.txt`. `.gitignore` excludes both folders. Ship
`processed/` and the code; let the replicator regenerate `results/`.

## Reproducibility notes

- Matching without replacement breaks ties by the current sort order. Each matching script
  therefore sets `set seed 20260727` and sorts on the grid-cell identifier before any
  `psmatch2` call, so the matched samples are deterministic.
- Multiple imputation in `11_survey_analysis.do` uses `rseed(1234)`.
- Add-on packages are pinned by vendoring rather than by version number; do not re-run
  `00_install_packages.do` unless you intend to update them.
- The package was verified against the published Supplementary Information before release:
  16 of the 17 code-generated tables reproduce exactly, and the matched samples are
  identical cell for cell to the archived ones. `docs/verification.md` reports the full
  comparison, including the one table that does not match.
- Building Figure S2 renders about 91,000 polygons five times. `run.do` sets
  `set graphics off` and clears graph memory between scripts to keep this stable in batch
  mode. If Stata terminates during an unattended run, re-run the affected script on its own;
  each script is self-contained and reads its inputs from `processed/`.

## Known discrepancies against the published Supplementary Information

Two SI figures in the published PDF contain errors that were traced to the code while
assembling this package. The package produces the corrected versions, so its output differs
visibly from the PDF in these two places. The estimates are unaffected in both cases.

1. **Figure S6, panels A and B.** The published labels, legend and panel title read "≤5km" /
   ">5km", but the variable plotted is defined at 2 km. The package produces the figure with
   correct 2 km labels. The 5 km specification is estimated separately and reported in
   Table S10.
2. **Figure S3, panel E.** The published version combined the bias-reduction plot from the
   miombo-classification matching run rather than the Hansen 20% run, because `gr combine`
   referenced a stale filename. The package produces panel E from the Hansen 20% run, as the
   caption states. Panels A to D are unaffected.

3. **Table S7 and Figure S5, the 30% robustness results.** The published Table S7 was
   produced by a 30% matching run without the 0.05 caliper, which is the paper's main
   matching specification. This package applies the caliper, consistently with the 20%
   analysis. The SCCP-area column that the main text cites (3.1 and 4.0 percentage points)
   is unaffected, because the caliper does not bind there. The spillover columns change: for
   the 10-km buffer the package gives 0.28\*\* and 0.22 against the published 0.95\*\*\* and
   1.64\*\*\*, on N of 255,440 rather than 306,640. Figure S5 shifts slightly for the same
   reason. `docs/verification.md` documents the diagnosis.

The code also produces a sixth subgroup table, effects on extrinsic motivations, which the SI
does not include. It ships as `results/diagnostics/diag_extrinsic_motivations.rtf`.

## Analyses not in the package

Several specifications were explored during development and cut before publication. They are
not included, so that the package contains only what the paper reports: an instrumental-variable
estimation of park employment using distance to the initial project village as an instrument
(dropped at the first revision because the exclusion restriction is not defensible), placebo
tests on pre-treatment years, a Hansen 10% canopy threshold branch, inverse-probability-weighted
specifications, a village-level forest-cover analysis, and a feasibility check against the JRC
Tropical Moist Forest product. `docs/crosswalk.md` records these.
